# 流式回答不做断点续传，重试只发生在首字节之前

SSE 链路上三个边界：客户端中途断开时，服务端立即 abort 上游请求，并把已生成的内容以 `status=ABORTED` 落库（用户刷新还能看到半截回答）；失败重试只覆盖**首字节之前**的失败（连接失败、5xx、超时），最多 2 次、500ms→1s 指数退避；一旦开始吐字就绝不重试；不做断点续传，另加 15s 心跳注释行防止反向代理超时。

## Considered Options

- **重试已开始的流**：两次输出会在客户端拼接，产生重复或错乱文本，且 token 已花掉，得不偿失。
- **断点续传**（记录已发送的 token 偏移、重连后从偏移继续）：需要服务端维护流状态、客户端维护偏移，还要处理"上游已中断但偏移记错"，工期至少 +3 天，对一个演示项目没有回报。
- **断开即丢弃半截回答**：实现更简单，但用户关掉页面再回来什么都看不到，丢掉了一个很便宜的体验点。

## Consequences

- `chat_message.status` 需要 `COMPLETED` / `ABORTED` / `FAILED` 三态，`ABORTED` 的消息在历史里照常展示。
- 前端重连意味着**重发一次提问**，因此明确不需要"断点续传"按钮；但"停止生成"按钮走 `AbortController`，与断开语义一致。
- 上游 abort 依赖模型 SDK/HTTP 客户端支持取消（`OkHttp` 的 `Call.cancel()`）。
