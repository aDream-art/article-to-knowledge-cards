# 删除会话时硬删消息，收藏改为存问答快照

会话删除是**物理删除**（会话 + 其消息），不做 `is_deleted` 软删；收藏表独立冗余保存 `question` / `answer` 文本、模型名与时间，因此原会话消失后收藏仍可读可检索，只是无法跳回原会话。

## Considered Options

- **软删会话与消息**：看似安全，但本项目是 MyBatis 手写 XML，十几条查询都要记得带 `and is_deleted = 0`，漏一条就产生脏数据；索引选择性也会变差。对一个演示项目，这是"看着优雅、实际最容易翻车"的负担。
- **收藏持外键、依赖软删保命**：删了会话后收藏会变成不可读的死链，等于把问题推给 UI。

## Consequences

- 收藏的语义被钉死为"留存物"而非"指针"，符合"换设备也找得到那条好答案"的初衷。
- 消息不可编辑（见 ADR 关于不做重新生成），因此快照不会过期。
- `favorite.session_id` 保留但不参与级联，仅用于展示来源；会话已删时前端不显示"跳转"入口。
