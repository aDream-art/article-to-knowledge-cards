# 90 秒演示脚本

录屏按这个顺序走，一条不落；每步都对应 README 验收清单里的编号。

## 0. 准备（录屏前，不入镜）

```bash
docker compose up -d --build
# 等 mysql healthy，再等 app 启动日志出现 "Started ChatApplication"
```

浏览器开两个窗口：`http://localhost:8081`（用户端）、`http://localhost:8080/swagger-ui.html`（可选，最后露一下）。

## 1. 注册登录（10s）

- 注册一个演示账号（自行设置密码，不要使用弱口令），直接进主界面。
- 一句台词："密码 BCrypt，JWT 7 天，登出会把 jti 写 Redis 黑名单 —— 无状态 token 也能主动失效。"

## 2. 会话隔离（15s）

- 新建会话 A，问："用三句话解释 Redis 缓存穿透。"
- 新建会话 B（这次选通义），问："我刚才问了什么？" —— 它答不出来。
- 回会话 A，问："继续刚才的话题。" —— 它记得。
- 台词："上下文窗口在 Redis，按会话隔离；MySQL 才是真相源，删缓存会从库里重建。"

## 3. 流式与中断（15s）

- 在会话 A 提一个长问题，等它吐字到一半，**点"停止生成"**。
- 刷新页面 —— 半截回答还在，状态是 `ABORTED`。
- 台词："首字节前可以重试和降级，开始输出后绝不重试，否则两段回答会拼歪；中断也要落库，这是'关掉页面回来还能看见'的代价最小的实现。"

## 4. 文档问答（20s）

- 上传一份 50KB 左右的 TXT（比如某篇技术长文）。
- 绑定到会话 B，问文档里的一个细节 —— 答对，末尾有"依据：片段 N"。
- 问一个文档里没有的东西 —— 明确回"文档未提及"。
- 台词："400 字切分、80 字重叠，通义 embedding 1024 维，MySQL 存 BLOB，Java 里算余弦取 top-5，阈值 0.3 以下直接拒答。没有向量库，因为一个文档就几百片。"

## 5. 限流（10s）

- 连点发送 21 次（或者用 swagger 打 21 次）。
- 第 21 次被拦住，前端顶部出现"请求过于频繁"。
- 台词："ZSET 滑动窗口 + Lua 原子执行，不存在固定窗口的临界双倍；配额按天算 token，超了是另一个错误码。"

## 6. 收藏与统计（15s）

- 回到一条好回答，点收藏，打两个标签。
- **删掉整个会话**，去收藏页 —— 那条问答还在，还能按标签筛出来。
- 打开统计页 —— 调用次数、token、Top 用户、14 天趋势。
- 台词："收藏存的是快照不是指针，所以删会话不会让收藏变死链；这是刻意的数据冗余。"

## 7. 收尾（5s）

- 露一眼 `/swagger-ui.html` 和 `docker ps` 的四个容器。
- 台词："一条 compose 起全栈，没有 Docker 也能按 README 本地跑。"

## 录屏禁忌

- 不要现场配 Key（网络抖动+可能失败），Key 提前放进 `.env`；mock 模式单独录一段 10 秒的"无 Key 也能跑"。
- 不要把终端里的 JWT 完整刷出来取景。
